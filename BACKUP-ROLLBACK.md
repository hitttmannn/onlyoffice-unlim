# Резервная копия и откат

Это план до обследования сервера, а не универсальный скрипт копирования БД.
Нет команды автоматического переключения: имена сервисов и хранение неизвестны.

## До любых изменений production

1. Определить Compose/project, image ID/digest 9.2.1, env/secrets, bind/volume,
   внешние БД и очередь. Сохранить локально в закрытый каталог с umask 077;
   не коммитить и не отправлять секретные конфиги в GitHub.
2. Сохранить старый образ через docker image save, проверить sha256 и возможность
   docker image load на стенде. Сохранить Compose, proxy и TLS, JWT и текущие
   ONLYOFFICE настройки Nextcloud. Секреты хранить зашифрованно отдельно.
3. Согласовать окно обслуживания: запретить новые редакторские сессии, дождаться
   сохранения и callback всех открытых документов. Обычная копия работающего
   PostgreSQL volume не является консистентным backup.
4. Сделать согласованные нативные дампы БД (pg_dump/pg_dumpall по фактической
   схеме), backup Nextcloud DB/config/data и хранилища документов. Для томов Docs
   применять документированное quiesce/snapshot или остановку в согласованное
   окно; не выполнять это сейчас. Учесть внешние БД, custom fonts и cache с
   ещё не сохранёнными изменениями. Не делать flush очередей/Redis вслепую.
5. Шифровать копию, хранить ещё одну вне nc, проверить checksum, свободное место,
   восстановление БД и документов в изолированных томах. Записать RPO/RTO по
   фактическому тесту; неподтверждённый backup не даёт права переключать.

## Переключение после подтверждения

Зафиксировать последние backup и старый endpoint. Завершить редакторские сессии.
Применить проверенный image digest 10 к отдельным проверенным данным по
поддерживаемому upstream пути миграции; не подключать новые сервисы к старым
production данным наугад. Изменить только согласованный endpoint/proxy или
настройку коннектора, проверить создание/сохранение тестового документа.
Не удалять старый образ, контейнер и backup.

## Откат

Триггеры: потеря сохранений/callback, ошибки JWT/TLS, OOM, повреждение документов,
регрессия мобильного UI или coediting. Сначала закрыть доступ к новым сессиям,
сохранить логи и все изменения после переключения. Вернуть старый endpoint и
9.2.1 с его оригинальной конфигурацией и совместимыми данными. Не запускать 9.2.1
на БД, которую мигрировала 10. При необходимости восстановить согласованную копию
в отдельные тома. Документы, изменённые после backup, сверить и перенести отдельно:
слепое восстановление Nextcloud backup потеряет новые правки. Повторить тест
сохранения; только затем открыть доступ пользователям.

Без изменения production прекращение staging: `docker compose --env-file
private.env stop`. Не применять `down -v`, prune и массовые stop/rm.
