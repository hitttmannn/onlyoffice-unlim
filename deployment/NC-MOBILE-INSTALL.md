# Развёртывание Docs 10 и собственного интерфейса на nc

Проверено локально на Nextcloud 35.0.2 и официальном connector 10.2.1. Приложение
onlyoffice_mobile использует проверки оригинального EditorApiController и
штатные download/callback endpoints, сохраняет исходные permissions и заново
подписывает дополненную конфигурацию тем же JWT. Штатные файлы коннектора не
изменяются. Новая панель отказывается от документов с запретом copy/download,
от отключённых администратором плагинов и от read-only/review-only документов.

## Что устанавливается

- Отдельный Docs 10.0.0-169 на 127.0.0.1:18082 с новыми именованными томами.
- Фоновый плагин с собственной панелью, без коммерческого mobile addon.
- Отдельное приложение /var/www/nextcloud/apps/onlyoffice_mobile.
- Отдельный маршрут https://nc.evgeny-a.ru:65443/oo10/ через Apache.
- Один IncludeOptional внутри единственного VirtualHost на порту 65443
  в /etc/apache2/sites-enabled/default-ssl.conf; исходник сохраняется privately.

По явному решению владельца старый контейнер удаляется до проверок на nc.
Сначала сохраняются согласованная копия его mounts после остановки и настройки.
Тома и образ не удаляются. Стандартный редактор будет недоступен от остановки
до переключения на новый Docs. prepare/activate сами URL не меняют; switch меняет.
Приложение по умолчанию допускает только администраторов. Использовать только
копии DOCX/XLSX в корне «Файлов» текущего пользователя. Word пока не сохраняет
внутреннее оформление изменяемого абзаца и не предназначен для сложных документов.

## Выполнение от root на nc

```sh
cd /root/onlyoffice-unlim
git pull --ff-only
python3 scripts/retire-old-onlyoffice.py &&
python3 scripts/nc-mobile-install.py prepare &&
python3 scripts/nc-mobile-install.py activate &&
python3 scripts/nc-mobile-install.py switch
```

prepare проверяет версию/состояние NC, коннектор 10.2.1, свободные RAM/диск,
работу старого контейнера либо запись о его удалении с холодной копией и отсутствие целевого приложения/прокси. Генерирует
закрытый env из текущего JWT коннектора (не выводит его), устанавливает файлы
нового приложения без включения, запускает только новый контейнер и ждёт health.

activate проверяет, что vhost и исходный URL коннектора не изменились с prepare.
Включает необходимые Apache proxy/http/headers modules, добавляет только /oo10/,
проверяет apache configtest перед graceful reload и HTTPS healthcheck с проверкой
сертификата. Только затем включает новое приложение. При ошибке удаляет свой
Include/proxy и пытается вернуть Apache, отключает только новое приложение.
Конфигурационный протокол ошибки лежит в private/nc-mobile/. При любых ошибках
остановиться и прислать обычный вывод, не содержимое private/. Повторный prepare
после частичного выполнения блокируется: не удалять каталоги вслепую.

Файлы с JWT и резервные конфиги не покидают nc и исключены из Git. Новые
Apache modules после неудачной активации могут остаться включёнными; они не
меняют маршрут старого Docs. Не перезапускать Docker/Apache вручную по общей
подсказке a2enmod: скрипт применяет проверенный graceful reload сам.

## Проверка пользователем

Открыть под администратором:
https://nc.evgeny-a.ru:65443/index.php/apps/onlyoffice_mobile/
Создать копии DOCX/XLSX в корне своих «Файлов», открыть через новую панель,
изменить, сохранить, закрыть и скачать через обычный Nextcloud. Проверить на
реальном телефоне, включая виртуальную клавиатуру, прокрутку и повторное открытие.

## Пользователи после первичной проверки

Для дополнительных пользователей предусмотрен app config allowed_users — JSON
массив точных UID. По умолчанию [] и доступ только администраторам. Включать
список после проверки, не менять группы admin ради панели. Допущенный
пользователь по-прежнему может редактировать только доступные ему файлы.
Публичные ссылки/гости и произвольные папки на этом этапе не поддержаны.

## Откат

```sh
cd /root/onlyoffice-unlim
python3 scripts/restore-old-onlyoffice.py
```

Восстанавливает контейнер из сохранённых Config/HostConfig с теми же оставленными
томами и bind-каталогами, запускает его и возвращает сохранённые URL коннектора.
Новый контейнер/маршрут остаются для диагностики. Старые данные при обычном откате
не распаковываются поверх существующих. Если данные потеряны, отдельно восстановить
холодный архив при остановленном контейнере; не распаковывать поверх работающей БД.
Образ при необходимости загружается из ранее сохранённого tar. Восстановление на
nc ещё не выполнялось: архив и сценарий не равнозначны проверенному восстановлению.

## Локальные результаты

Подписанный config, открытие/изменение/forcesave DOCX и XLSX, скачивание через
Nextcloud WebDAV и наличие уникального текста в реальных архивах проверены.
Повторены через /oo10/ на локальном Apache при неизменённом основном URL.
Чужой fileId отвергнут 403; пользователь вне допуска — 403; save без CSRF — 412.
Сценарии prepare/activate/switch и rollback configtest дополнительно проверены с fake
командами во временных каталогах (без root/реальных сервисов). TLS/public NAT
на nc и реальные Android/iOS ещё требуют проверки там.

Основа reverse proxy:
https://helpcenter.onlyoffice.com/docs/installation/docs-community-proxy.aspx
https://github.com/ONLYOFFICE/document-server-proxy/blob/master/apache/proxy-to-virtual-path.conf

## Обновление 0.2.0: масштаб и мобильное открытие по умолчанию

```sh
cd /root/onlyoffice-unlim
git pull --ff-only
python3 scripts/update-mobile-panel.py
```

Сохраняет предыдущие файлы в private/mobile-ui-before-*, обновляет только свою
панель и регистрирует глобальный middleware отдельного приложения. Штатный
коннектор не патчится, контейнер Docs не пересоздаётся. occ upgrade регистрирует
версию приложения (на короткое время включает maintenance); при уже ожидающем
обновлении Nextcloud скрипт отказывается продолжать.

В мобильном браузере и Android WebView обычный маршрут ONLYOFFICE DOCX/XLSX
перенаправляется в собственную панель для уже допущенных пользователей. Desktop,
публичные ссылки, шаблоны, read-only и остальные форматы сохраняют прежнее открытие.
Android Direct Editing проверяется штатным механизмом одноразового токена; затем
панель требует обычную веб-сессию. Если приложение не передаёт cookies, нужен
вход в веб-окне один раз. Bearer-токены приложения и signed references не
копируются в URL панели. Проверка реального Android-клиента на nc ещё нужна.

Масштаб документа: 50–200%, кнопки −/+ и сброс. Браузерный pinch zoom разрешён,
но отдельные Android WebView могут управлять им самостоятельно. После обновления
закрыть старый редактор и открыть файл заново (при необходимости обновить страницу).

Для отключения только автоматического направления:
```sh
sudo -u www-data php /var/www/nextcloud/occ config:app:set onlyoffice_mobile mobile_default --value=no
```

## Явный выбор листа XLSX

Над таблицей расположен блок «Лист книги» со списком листов и номером текущего.
При переключении очищается поле редактирования старой ячейки. Для Word блок скрыт.
Для обновления только интерфейса на уже установленной версии 0.2.0:

```sh
git pull --ff-only
python3 scripts/update-mobile-panel.py --ui-only
```

Этот режим сохраняет предыдущие три UI-файла, не запускает occ upgrade,
не меняет версии приложений и не переводит Nextcloud в maintenance.

## Лимит памяти Docs на nc

Лимит production-сервиса docs увеличен до 4 ГиБ RAM. `memswap_limit: 4608m`
задаёт общий потолок RAM+swap: 4 ГиБ RAM и до 512 МиБ swap. Это потолок,
не предварительное выделение всей памяти. Применение к существующему контейнеру
без пересоздания (после git pull):

```sh
docker update --memory 4g --memory-swap 4608m onlyoffice-unlim-nc-mobile-docs-1
```

Compose хранит те же значения для следующих пересозданий. Этот раздел относится
к конкретному nc, а не меняет начальные лимиты переносимого compose.mobile.yaml.
