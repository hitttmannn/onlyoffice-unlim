## Фаза 1: подготовка материалов для отката без остановки

```sh
cd /root/onlyoffice-unlim
git pull --ff-only
python3 scripts/prepare-nc-backup.py --save-image
```

Путь /root/onlyoffice-unlim соответствует показанному пользователем сеансу;
если clone находится иначе, перейти в фактический каталог. Запускать как root.
Скрипт сохраняет inspect контейнера/образа, конфигурацию приложения ONLYOFFICE,
Nextcloud config, оригинальные файлы connector и tar старого образа с SHA256.
Измеряет все семь mount sources и свободное место. Каталог private/ закрыт
0700, новые файлы создаются с umask 077 и исключены Git. Внутри есть секреты:
не присылать, не публиковать, для внешнего хранения сначала зашифровать.
Копия app/config сделана на работающем сервере и не является согласованной
копией БД или данных Nextcloud. Запуск не останавливает и не удаляет контейнер.
Скрипт не проверяет совпадение image ID с историческим значением: сохраняет
фактически работающий контейнер и выводит image ID для сверки.

Публиковать можно только напечатанный summary-shareable.json. При ошибке
сохранения не считать частично созданный каталог завершённой подготовкой.

## Фаза 2: интеграция (ещё не готова)

Нужно связать mobile UI с штатными endpoints коннектора, а не отдавать реальные
файлы через локальный тестовый server.py. Сохранить Nextcloud authorization,
file/share permissions, подписанный editor config, download URL и callbacks.
В проверенном исходном connector 10.2.1 EditorApiController меняет type на mobile
по User-Agent и подписывает весь config после setCustomization/setWatermark.
Любые plugins/type-настройки должны попадать в config до подписи. Параметр
$desktop этого controller связан с другим поведением UI и сам по себе не
отключает ветку мобильного User-Agent. Совпадение номера версии не доказывает
совпадение SHA/содержимого установленного приложения.

Сначала отдельная тестовая группа/пользователь и копии файлов; обычные
пользователи продолжают работать на старом сервере. Нельзя заменять общий
DocumentServerUrl до проверки. Изменение подписанного официального приложения
может вызвать integrity-check: подготовить отдельное расширение либо
поддерживаемый fork с понятным обновлением, не редактировать minified assets
на рабочем сайте вслепую.

## Фаза 3: согласованная копия и переключение

Только после готовности интеграции. Завершить сессии двух пользователей,
дождаться сохранения, затем в согласованное окно сделать согласованные дампы
фактических БД и копию всех томов/хранилищ; проверить восстановление. Живой tar
PostgreSQL volume использовать как backup нельзя.

После успешного теста переключить согласованный endpoint. Старый контейнер
сначала остановить и сохранить для отката. Удаление контейнера допустимо после
проверки нового пути и восстановления; тома и backup не удалять. Не запускать
новую версию на старой БД, не использовать docker prune или rm -v.
