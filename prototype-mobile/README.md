# Собственный упрощённый интерфейс DOCX/XLSX — прототип 0.0.1

Работает через открытый API собственного фонового плагина поверх desktop-движка
ONLYOFFICE Docs 10.0.0-169. Это отдельная мобильная страница; коммерческий mobile
addon не используется. Пока работает только с двумя локальными тестовыми файлами.
Не является готовой интеграцией Nextcloud.

## Возможности

DOCX: список абзацев, изменение текста выбранного абзаца, добавление абзаца.
XLSX: изменение ячейки, добавление/удаление строки или столбца у выбранной ячейки,
выбор листа. Табличный просмотр пока ограничен A1:H20. Сохранение подтверждается
только после подписанного callback и записи файла, а не после клика кнопки.

## Ограничения

Word пока только для простых текстовых абзацев: изменяемый абзац пересоздаёт
содержимое и может потерять оформление/встроенные объекты. Прочие абзацы не
переписываются как plain text всего документа. Простая формула B1*2 проверена с добавлением и удалением строки/столбца.
Проверки сложного DOCX, сложных формул, объединённых ячеек и совместного редактирования ещё не завершены. Реальная
экранная клавиатура Android/iOS требует отдельных тестов. Нельзя загружать
рабочие документы; HTTP-сервис предназначен только для localhost-стенда.

## Локальный запуск

```sh
cd prototype-mobile
python3 setup.py
docker compose --env-file local.env up -d
```

Дождаться healthcheck: `curl -fsS http://127.0.0.1:18780/healthcheck`.
Открыть http://127.0.0.1:18781/ на том же компьютере. Порты 18780/18781 должны
быть свободны. Нельзя заменять localhost binding на 0.0.0.0: аутентификации
пользователей в экспериментальном backend нет. JWT включён для Docs и callback.
Для телефона далее нужен защищённый доступ с согласованными адресами, без
публикации экспериментального сервиса в Интернет.

Остановка только этого стенда: `docker compose --env-file local.env stop`.
Тестовые файлы и журнал callback находятся в data/, секрет — local.env; всё
исключено из Git. Сохраните data/ перед удалением стенда. Изменение JWT требует
перезапуска сервиса и не должно выполняться при открытых документах.

## Автоматический браузерный тест

Требует Node.js и devDependency Playwright из package.json. Можно использовать
уже установленный браузер через PLAYWRIGHT_BROWSER_PATH. По умолчанию Playwright
ожидает свой Chromium. `node mobile-test.cjs sample.docx` и аналогично sample.xlsx.
Тесты изменяют только sample-файлы, запускают профиль Android с viewport 390x844
и проверяют операции UI и callback-сохранение. Это эмуляция, не тест на телефоне.
